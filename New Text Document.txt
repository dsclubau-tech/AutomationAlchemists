## Blocker 1 — Step 1 would break the Return Label Converter

`src/lib/supabase/proxy.ts` is middleware guarding the **entire app**. Everything except `/auth/*`, `/login`, `/register`, `/privacy` redirects to `/login`:

```ts
if (!user && !isAuthRoute && !isLoginRoute && !isRegisterRoute && !isPrivacyRoute) {
  redirectUrl.pathname = "/login";
```

`/main` (Return Converter), `/account`, and `/choose` all depend on it. "Remove CP Bot's own signup/login pages" removes the Return Converter's login too — directly against your standing instruction. Only the `/cp-bot/*` redirects can be repointed at AA without collateral damage.

## Blocker 2 — the callback as written won't log anyone in

The sample calls `supabase.auth.setSession()` client-side, which writes to **localStorage**. This app's middleware and every server component read **`sb-*` cookies**. A localStorage-only session means the user still appears signed out on every server-rendered page — an infinite redirect back to AA. The callback must set cookies server-side (a Route Handler using `@supabase/ssr`), not the client-side snippet provided.
